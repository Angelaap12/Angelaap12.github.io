Case study: Brutus

An SSH brute-force investigation on Hack The Box — how I connected auth.log, wtmp, and sudo records into one timeline. Full write-up in the Sherlock repo above.

$ grep "Failed password" auth.log | head Failed password for root from 65.2.161.68 Failed password for admin from 65.2.161.68 Failed password for svc_account from 65.2.161.68 $ grep "Accepted password" auth.log Accepted password for root from 65.2.161.68 port 53184 $ grep "new user" auth.log useradd: new user: name=cyberjunkie, UID=1002 $ grep "sudo:" auth.log cyberjunkie : COMMAND=/usr/bin/cat /etc/shadow

Reconstructed timeline — Mar 6, 2024 (UTC)

  1. 06:31:31
    Burst of failed SSH logins from 65.2.161.68 across multiple usernames
  2. 06:32:44
    Successful root authentication from the same IP
  3. 06:34:18
    New account cyberjunkie created during the root session
  4. 06:35:15
    cyberjunkie added to the sudo group — persistence established
  5. 06:37:57
    cyberjunkie reads /etc/shadow via sudo
  6. 06:39:38
    cyberjunkie uses sudo curl to fetch an external shell script
What I learned

No single log told the story. SSH records showed initial access, wtmp confirmed the sessions, and account/sudo events showed what the attacker did with it. I also had to work around a missing utmpdump by extracting it from a Debian package — evidence is only useful if you can actually read it.
